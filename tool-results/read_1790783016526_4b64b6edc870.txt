    40→    40→
    41→    41→**All templates MUST obey these.**
    42→    42→
    43→    43→```
    44→    44→W = page total width
    45→    45→H = page total height
    46→    46→U = W * 0.05           # Base spacing unit (5% of page width)
    47→    47→                        # All spacing should be multiples of U
    48→    48→```
    49→    49→
    50→    50→**Coordinate origin:** `(0, 0)` at top-left corner. Some PDF libraries (ReportLab) use bottom-left origin - invert Y axis accordingly: `y_pdf = H - y_spec`.

    53→    53→
    54→    54→## A0.1 - Absolute Anchor Grid (Replaces Flow Layout)
    55→    55→
    56→    56→**Old (DEPRECATED):** `Y = previous_element_Y + height + spacing` - if one element overflows, everything below shifts and gets crushed.
    57→    57→
    58→    58→**New (MANDATORY):** Page height = 100%. Every element group gets an **absolute percentage Y-anchor**. Elements may only grow **within their own bounding box**. They NEVER push or compress other blocks.
    59→    59→
    60→    60→### Implementation Rule
    61→    61→
    62→    62→```
    63→    63→# WRONG - flow layout (banned)
    64→    64→y_cursor = PAGE_H - top_margin
    65→    65→y_cursor -= title_height
    66→    66→y_cursor -= gap
    67→    67→y_cursor -= subtitle_height   # ← if title wraps, subtitle gets crushed
    68→    68→
    69→    69→# RIGHT - absolute anchor grid
    70→    70→ANCHOR_TITLE_Y  = H * 0.30
    71→    71→ANCHOR_SUMMARY_Y = H * 0.50
    72→    72→ANCHOR_META_Y   = H * 0.70
    73→    73→ANCHOR_FOOTER_Y = H * 0.90
    74→    74→# Each block renders at its anchor, independent of others
    75→    75→```
    76→    76→
    77→    77→### Bounding Box Containment
    78→    78→
    79→    79→Each block has a **maximum bounding box** defined by two consecutive anchors:
    80→    80→- Block can grow downward within `[own_anchor_Y, next_anchor_Y - min_gap]`
    81→    81→- If content exceeds its bounding box → trigger overflow protection (see Part 3)
    82→    82→- Blocks NEVER consume space belonging to adjacent blocks
    83→    83→

    87→    87→

    99→    99→###  Data-to-Drawer Binding Rule
   100→   100→
   101→   101→> **Hero Title = Company/entity name. Kicker = Report type/subtitle. Never reverse.**
   102→   102→
   103→   103→When users provide structured information (company name + report name/type), they must be bound to typography drawers by these rules:
   104→   104→
   105→   105→| User Data Field | Bound to Typography Role | Notes |
   106→   106→|-------------|-------------|------|
   107→   107→| **Company/entity name** (e.g. "GREENTECH") | **Hero Title** (45-65pt Heavy) | Company name is the **absolute visual center**, largest font, heaviest weight |
   108→   108→| **Report type/subtitle** (e.g. "2025 Annual Report Summary") | **Kicker** (16pt, letter-spacing 3pt, opacity 60%) | Report name is decorative supplementary text, placed in small text position at top-left/above title |
   109→   109→| **Summary/description** | **Summary** (16-18pt) | Detailed description text |
   110→   110→| **Date/author/version** | **Meta** (20-22pt) | Auxiliary information |
   111→   111→| **Document number/org signature** | **Footer** (16pt, opacity 60%) | Bottom closing |

   114→   114→1. If user provides only one name → treat as company/entity name, bind to Hero Title
   115→   115→2. If user provides two names → shorter/more brand-like → Hero Title; longer/descriptive → Kicker or Summary

   119→   119→### The Summary Block Rule (Anti-Void Iron Rule) 
   120→   120→
   121→   121→> Every cover MUST include a Summary/Description text block. If the user provides no summary, the system MUST auto-generate one.
   122→   122→
   123→   123→**Why:** A cover with only a title and date looks barren. The Summary block physically fills 2-4 lines of space, preventing the "empty field" aesthetic.
   124→   124→
   125→   125→**Auto-generation rule:** When no summary/description is provided:
   126→   126→```python
   127→   127→# Generate a default summary
   128→   128→if not summary_text:
   129→   129→    summary_text = f"This report was generated by {org_name or 'the system'}, containing comprehensive data analysis and insights."
   130→   130→    # Or in English:
   131→   131→    # summary_text = f"This report presents comprehensive analysis and key insights prepared by {org_name or 'the organization'}."
   132→   132→```
   133→   133→
   134→   134→**Constraints:**
   135→   135→- Width: template-specific (typically `W * 0.5` to `W * 0.6`)
   136→   136→- Lines: 2-4 lines (auto-wrap at width boundary)
   137→   137→- Never truncate summary - if too long, reduce to 4 lines max with `...`
   138→   138→
   139→   139→### Font Weight Fallback
   140→   140→
   141→   141→- If font family lacks Black/Heavy weight → use Bold + slightly larger size (+4pt)
   142→   142→- If font family lacks Light weight → use Regular + increased letter-spacing (+1pt)

   148→   148→## A0.3 - Z-Index Layer Management
   149→   149→
   150→   150→All cover elements must be rendered in strict layer order. No exceptions.
   151→   151→
   152→   152→| Layer | Z-Index | Contents | Rules |
   153→   153→|-------|---------|----------|-------|
   154→   154→| **Layer 0** (base) | 0 | Background fill (white / light gray) | Always rendered first; full page |
   155→   155→| **Layer 1** (background) | 1 | Grids, watermark letters, decorative blocks, large clipped graphics | **MUST enable clip-path** - background elements may extend beyond logical bounds but must be clipped to page physical bounds. Never let background elements inflate PDF page size. |
   156→   156→| **Layer 2** (structure) | 2 | Ultra-thin divider lines, sidebars, corner crop marks | Structural guides that define spatial zones |
   157→   157→| **Layer 3** (content) | 3 | All readable text content | Rendered last, always on top |
   158→   158→
   159→   159→### Clip-Path Enforcement
   160→   160→
   161→   161→```css
   162→   162→/* clip background overflow — ONLY on Layer 1 */
   163→   163→.cover-bg-layer {
   164→   164→  position: absolute;
   165→   165→  inset: 0;
   166→   166→  overflow: hidden;  /* MANDATORY */
   167→   167→  z-index: 1;
   168→   168→}
   169→   169→```
   170→   170→
   171→   171→> ⚠️ **Clip scope = Layer 1 ONLY.** `overflow: hidden` must ONLY be on the Layer 1 background container. Layer 2 (lines) and Layer 3 (text) containers must NOT have `overflow: hidden`.
   172→   172→
   173→   173→###  Anti-Clip Bug (Layer 3 Text Truncation Fix)
   174→   174→
   175→   175→**Symptom:** Cover text is visible but truncated by an invisible boundary.
   176→   176→
   177→   177→**Root cause:** `overflow: hidden` scope too broad, clipping text in Layer 3.
   178→   178→
   179→   179→**Iron rule:**
   180→   180→```html
   181→   181→<!-- ✅ CORRECT - overflow:hidden only on Layer 1 -->
   182→   182→<div class="cover-layer-1" style="position:absolute; inset:0; overflow:hidden; z-index:1;">
   183→   183→  <!-- Background decorative elements -->
   184→   184→</div>
   185→   185→<div class="cover-layer-2" style="position:absolute; inset:0; z-index:2;">
   186→   186→  <!-- Structure lines, no overflow:hidden -->
   187→   187→</div>
   188→   188→<div class="cover-layer-3" style="position:absolute; inset:0; z-index:3;">
   189→   189→  <!-- Text content, no overflow:hidden -->
   190→   190→</div>
   191→   191→
   192→   192→<!-- ❌ WRONG - global overflow:hidden clips text -->
   193→   193→<div class="cover-container" style="overflow:hidden;">
   194→   194→  <div class="layer-1">...</div>
   195→   195→  <div class="layer-2">...</div>
   196→   196→  <div class="layer-3">...</div>  <!-- Text gets clipped! -->
   197→   197→</div>
   198→   198→```
   199→   199→
   200→   200→###  No Page Border/Frame
   201→   201→
   202→   202→**Symptom:** A rectangular border appears around the entire cover page.
   203→   203→
   204→   204→**Iron rule:**
   205→   205→```css
   206→   206→.cover-page {
   207→   207→  border: none !important;
   208→   208→  outline: none !important;
   209→   209→  box-shadow: none !important;
   210→   210→}
   211→   211→```
   212→   212→
   213→   213→###  Minimum Spacing Between Decorative Lines and Text (Line-to-Text Spacing)
   214→   214→
   215→   215→**Symptom:** Decorative lines on the cover (Layer 2 dividers, corner marks, sidebar edges) are flush against or overlapping with text.
   216→   216→
   217→   217→**Iron rule:**
   218→   218→```
   219→   219→Minimum spacing between decorative lines and any text content = U (= W * 0.05)
   220→   220→i.e., at least 1 U of whitespace between line edges and text edges
   221→   221→```
   222→   222→
   223→   223→| Line Type | Minimum Spacing | Notes |
   224→   224→|---------|---------|------|
   225→   225→| Horizontal divider | `U` above and below the line | Line must not be flush against title or body text |
   226→   226→| Vertical sidebar edge | `U` to the right of the line | Text inside sidebar must maintain spacing from the edge |
   227→   227→| Ultra-thick anchor line (Template 01) | `2 * U` to the right of the line | Thick line and title need ample breathing room |

   301→   301→## S3.0 - Cover Overlap Validation (MANDATORY)
   302→   302→
   303→   303→**After generating the cover HTML and before rendering to PDF, run:**
   304→   304→
   305→   305→```bash
   306→   306→node "$PDF_SKILL_DIR/scripts/cover_validate.js" cover.html
   307→   307→```

   310→   310→

   312→   312→

   314→   314→1. Adjust the decorative line's Y position to maintain ≥ 1U gap from the nearest text
   315→   315→2. Or adjust the text block's position/size to avoid the overlap
   316→   316→3. Re-run `cover_validate.js` until it passes (exit code 0)

   320→   320→## S3.1 - Hero Title Overflow Protection (Title Line-Wrapping)
   321→   321→
   322→   322→**Rule:** Hero title must NEVER exceed its template's width boundary.
   323→   323→
   324→   324→1. If rendered width > max_width → word-wrap (CJK: any character; Latin: space/hyphen)
   325→   325→2. Multi-line hero titles: **lock line-height to 1.15**
   326→   326→3. Maximum lines: **3** — if 4+ lines needed, reduce font size by 4pt increments
   327→   327→4. Minimum font size floor: **32pt** (below this, truncate with `...`)

   330→   330→
   331→   331→| Lines | With subtitle | Without subtitle |
   332→   332→|-------|--------------|------------------|
   333→   333→| 1 | ≤ 80pt | ≤ 80pt |
   334→   334→| 2 | ≤ 55pt | ≤ 70pt |
   335→   335→| 3 | ≤ 42pt | ≤ 48pt |

   429→   429→| **Dense** (fill > 80%) | `H * 0.20` | `H * 0.40` | `H * 0.65` |

   437→   437→- [ ] No cover has >40% dead whitespace at the bottom

   439→   439→- [ ] Sparse-content covers use centered distribution

   443→   443→## S3.9 - Percentage Positioning Requires Known-Size Container
   444→   444→
   445→   445→**Problem:** `top: XX%` resolves against containing block’s height. If height is undefined (all children absolutely positioned), percentages collapse and elements stack.
   446→   446→
   447→   447→**Iron rule:** Container with `top: XX%` children MUST have deterministic height (`height: 100%`, `inset: 0`, or `top` + `bottom` pair).
   448→   448→
   449→   449→```css
   450→   450→/* ✅ Safest: flat structure with px values */

   466→   466→# PART 4: COVER COLOR RULES
   467→   467→
   468→   468→> Cover colors must be consistent with the body color system - they cannot exist independently.
   469→   469→> **The cascade palette CSS output includes `--c-*` aliases** that map directly to cover template variables. Paste the CSS output into cover HTML's `:root` block — template 01 works without any manual color translation.
   470→   470→
   471→   471→```
   472→   472→Cover primary    = Body theme color
   473→   473→Cover secondary  = Primary lightness variant (±20% lightness)
   474→   474→Cover background = Pure white / very light gray / primary at 5-8% opacity
   475→   475→```
   476→   476→
   477→   477→### Absolutely Forbidden
   478→   478→
   479→   479→- ❌ Dark large-area solid backgrounds (dark blue, dark green, black filling the page)
   480→   480→- ❌ Gradient backgrounds (any `linear-gradient` / `radial-gradient` as large-area fill)
   481→   481→- ❌ High-saturation color schemes
   482→   482→- ❌ Rainbow / multi-color gradients
   483→   483→- ❌ Dense textures or patterns
   484→   484→- ❌ Piling on decorative elements - restraint > clutter
   485→   485→- ❌ More than 2 typefaces on a cover
   486→   486→- ❌ Centered text + gradient/solid background (PowerPoint aesthetic)
   487→   487→

   513→   513→# PART 4.5: ACADEMIC COVER TEMPLATES (Templates 03-04)
   514→   514→
   515→   515→> **Academic covers are exempt from PART 4 color rules.** Academic papers, theses, and research reports traditionally use dark backgrounds with light text - this is the established scholarly visual language. Templates 03-04 follow LaTeX title page conventions translated to HTML/CSS.
   516→   516→
   517→   517→**All 2 templates share these rules:**
   518→   518→- Page size: `width: 794px; height: 1123px` (A4 at 96dpi)
   519→   519→- Full-bleed dark background (edge-to-edge, no margins)
   520→   520→- Serif font for titles (Playfair Display / Noto Serif SC), sans-serif for metadata
   521→   521→- Generated as HTML → Playwright `page.pdf()` → pypdf merge (same pipeline as Report covers)
   522→   522→- `<link>` tag for Google Fonts (NOT `@import`)

   529→   529→| `subtitle` | Optional | Subtitle or abstract excerpt |
   530→   530→| `authors` | **Required** | Author name(s) |
   531→   531→| `institution` | Optional | University / lab / affiliation |
